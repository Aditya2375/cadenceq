02 / THE CONTRACT

Small rules.
Different outcomes.

Scheduling policies trade response for completion. None wins every workload. This model knows the length of the current CPU burst, unlike a general-purpose OS.

01 / FCFS

Keep your place.

The oldest ready task keeps the worker until its current CPU burst ends. New short tasks can wait behind a long one.

02 / ROUND ROBIN

Pass it around.

Run for a fixed quantum, then rejoin the queue. Arrivals and wakeups at the exact boundary enter before the expired task.

03 / SJF

Short burst first.

Pick the shortest known current CPU burst when the worker becomes free. Do not interrupt a running burst.

04 / SRTF

Let a shorter one in.

Reconsider after every callback. A strictly shorter remaining burst can take the next turn. On a tie the current task stays.

At each boundary

Finish the prior unit → complete or sleep → admit arrivals and wakeups in workload order → requeue an expired RR task. A sleep of 2 at clock 3 wakes at 5. Ties use queue-entry order. No context-switch overhead is modeled.

03 / KNOW THE EDGES

A scheduler,
not an operating system.

Cadenceq selects and invokes real work callbacks, one unit at a time, on one cooperative worker. The browser uses a fixed checksum program; native Python exposes the callback interface. All time shown is modeled, not a performance benchmark.

Read the implementation ↗
No forced interruption
A callback is atomic and trusted. A blocked or infinite callback blocks this scheduler. SRTF only switches between returned callbacks. No threads, host priorities or arbitrary-code sandbox.
Bounded by design
1..12 tasks, up to 7 alternating CPU/sleep bursts each, 1..64 units per burst, arrival 0..128, quantum 1..32 in the library. Workloads need a conservative horizon of 4096 ticks or fewer.
No real I/O or hidden work
Sleep is a logical waiting interval, not a timer or I/O request. A failing native callback consumes a tick, fails that task and is never retried. Cancel acts between ticks and does not undo work.
Local and temporary
No uploads, network, storage, telemetry or user-supplied code in this app. Reset and closing the tab lose the workload. Checksum output is a deterministic work receipt, not cryptographic authentication.
